/ the problem

Access reviews break down because real access lives everywhere.

HR systems, IdPs, GitHub, directories, SaaS apps, cloud roles, service accounts, spreadsheets. Auditors and customers ask for a single answer — the data is scattered and stale, so reviews turn into screenshot archaeology, and AI agents are multiplying the identities you have to govern. Even tools that aggregate it rarely tell you what the data can actually prove: how fresh it is, whether the sync was complete, or whether “absent” really means removed.

01 / see it

Every account, entitlement, and grant — one queryable graph.

Import HR identities, connect systems, and let reconciliation correlate accounts to people. A deterministic policy engine turns the graph into findings: orphaned accounts, terminated users with live access, privileged access without an owner, unused grants — each with evidence attached, not just a dashboard number. And the graph doesn’t overstate access: when a successful full sync stops reporting a grant, Sunder retires it under strict safety rules instead of letting it linger as “active” forever.

02 / decide it

Reviews and approvals people actually complete.

Scoped campaigns and finding-triggered micro-reviews land as assigned tasks in the web Governance Inbox — with Slack and Teams delivery where configured, and documented fallbacks where not. Every decision records who, why, and what they saw.

03 / prove it

Evidence assembled as you work — not the week before the audit.

Sync summaries, findings, review decisions, rationale, and provisioning actions accumulate in a durable evidence store. Export bundles map to SOC 2-style control objectives with explicit coverage notes and disclaimers — review-ready, without claiming certification.

/ the evidence model

Answers you can defend, by construction.

Most governance tools show you a dashboard and ask you to trust it. Sunder is being rebuilt on a canonical data plane — landing with design-partner pilots — where trust is structural: every fact knows where it came from, syncs land atomically or not at all, and the system tells you plainly what each source can and cannot prove.

Syncs land atomically — or not at all

Each connector sync commits as one sealed, numbered publication with a receipt: graph changes, observations, cursors, and evidence advance together. Reviewers never see a half-applied sync, and a listing never silently mixes two different states of the world.

Every fact carries provenance

Each observation names the exact tenant, system, connector, scope, collection, sync run, and publication that produced it. When an auditor asks “how do you know?”, the answer is in the record — not in someone’s memory of a sync job.

Absence is proven, not assumed

“Access removed” is only concluded from a complete, comparable enumeration of the exact collection that owned it. Partial, failed, or permission-limited syncs never silently delete — and a grant observed by two sources survives the loss of one.

Authority is policy, not write order

HR sources own workforce truth — lifecycle, manager, employment — by explicit, versioned policy. An application connector can never silently become the authority on a person, and when equally ranked sources disagree, Sunder records a visible conflict instead of letting the last write win.

The canonical data plane is merged and certified behind a strict contract suite on PostgreSQL and SQLite; it activates for pilots in one clean cutover rather than a risky in-place migration. Until then, pilots run on today’s shipped governance loop — and we will tell you plainly which guarantees apply to which.

/ security & compliance faq

The questions your security team will ask.

Do you replace Okta, Entra, or our HRIS?

No. Sunder sits above identity and access systems to govern visibility, reviews, evidence, and remediation.

Can we start read-only?

Yes. Read-only with manual remediation is the preferred pilot posture. Automated writes are only used for explicitly supported connector operations, with customer opt-in, approval boundaries, audit, and reconciliation.

Do you need production credentials?

Only customer-approved scopes for selected systems. Exports or fixtures can be used first where appropriate.

What happens when a sync fails halfway?

Nothing you have to distrust. On Sunder’s canonical data plane, a sync commits as one atomic, numbered publication with a receipt — the graph either advances to a complete new state or stays exactly where it was. Partial reads never leak into what reviewers see, and a lost response is recovered from the receipt rather than re-applied.

How do you avoid falsely concluding access was removed?

Absence has to be earned. A grant is only retired when the collection that owns it completes a full, comparable enumeration that omits it — today’s shipped sync path already enforces this with strict safety rules, and the canonical model deepens it with per-source observations, so evidence from one source is never erased by another source’s bad day.

Which system wins when sources disagree about a person?

An explicit, versioned authority policy — not write order. HR sources own workforce lifecycle by default; an IdP can be a configured fallback; application connectors can never silently become the authority. Equal-rank disagreement is recorded as a visible conflict with both claims kept as provenance.

Can Sunder support auditors?

The goal is review-ready evidence for implemented workflows — campaign decisions, rationale, audit trails, and selected SOC 2 ITGC mappings with explicit disclaimers. We do not claim certified compliance outcomes.

Do AI agents change access?

No autonomous destructive actions. Agent and MCP support starts with governed questions and bounded requests through Sunder’s API, policy, approval, and audit surfaces.

What does success look like?

A scoped identity/access graph, actionable findings, a completed review campaign, review and approval decision evidence, and an evidence export accepted by your security/GRC owner.
