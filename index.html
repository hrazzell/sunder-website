/ the problem

Access reviews break down because real access lives everywhere.

HR systems, IdPs, GitHub, directories, SaaS apps, cloud roles, service accounts, and spreadsheets. Auditors and customers ask for a single answer — but the data is scattered and stale.

Screenshot archaeology

Reviews rely on exports, screenshots, and spreadsheet reconciliation. Evidence collection is manual and repeated every audit cycle.

Access nobody can explain

Orphaned accounts, stale grants, and over-privileged access accumulate quietly — and are hard to justify when a customer security review asks.

Agents raise the stakes

AI agents and service accounts multiply identities and automated actors. Governance needs to be programmable and auditable before agents act on access.

/ how it works

One governed loop, from raw access data to accepted evidence.

Sunder builds a normalized access graph, identifies review-worthy findings, runs scoped access reviews and approval tasks, routes human decisions through web and chat surfaces, and produces durable evidence tied to observed access and decisions.

  1. 01

    Ingest

    Import HR/CSV identities and connect systems like GitHub, Okta, Microsoft Entra, Google Workspace, Slack, SCIM, LDAP, and REST sources.

  2. 02

    Correlate

    Normalize accounts and entitlements into one identity graph, correlate them to people, and surface unresolved accounts instead of hiding them.

  3. 03

    Detect

    A deterministic policy engine flags orphaned, stale, over-privileged, expired, and unresolved access as evidence-ready findings.

  4. 04

    Review

    Run scoped campaigns or finding-triggered micro-reviews. Reviewers decide in the web Governance Inbox, with Slack/Teams delivery where configured.

  5. 05

    Remediate

    Governed, approval-bounded provisioning where connectors support it — audited manual-fallback tasks everywhere else. No silent writes.

  6. 06

    Prove

    Export campaigns, decisions, rationale, sync summaries, and audit trails as evidence bundles your security/GRC owner can hand to an auditor.

/ api & agents

Built API-first. Agent-ready by architecture, not bolted on.

REST is the single external control plane — the web console, the operator CLI, chat delivery, and the MCP server are all clients of the same API. Agents can ask governed questions and submit bounded requests; they never get autonomous destructive access changes outside policy, approval, and audit boundaries.

REST API

Every governance operation — sync, findings, reviews, requests, approvals, evidence — is a documented API call with OIDC auth and audit logging.

Operator CLI

A thin, scriptable sunder CLI that maps 1:1 to the API, with --dry-run to render any request before it is sent.

MCP server

A first-class agent interface with bounded tool visibility and audited execution — agents are operators of Sunder and subjects governed by it.

Web + chat

A web Governance Inbox as the reliable baseline, with configurable Slack and Teams delivery for reviews and approvals, and documented fallbacks.

/ scope, honestly

What Sunder is not.

Sunder is not an IdP replacement, HRIS replacement, SIEM, PAM, or a broad compliance-certification engine. It sits above the systems you already run. Early design partners get a focused governance layer for visibility, review, evidence, and governed remediation — and we will tell you plainly where a connector or workflow is not mature yet.

/ security & compliance faq

The questions your security team will ask.

Do you replace Okta, Entra, or our HRIS?

No. Sunder sits above identity and access systems to govern visibility, reviews, evidence, and remediation.

Can we start read-only?

Yes. Read-only with manual remediation is the preferred pilot posture. Automated writes are only used for explicitly supported connector operations, with customer opt-in, approval boundaries, audit, and reconciliation.

Do you need production credentials?

Only customer-approved scopes for selected systems. Exports or fixtures can be used first where appropriate.

Can Sunder support auditors?

The goal is review-ready evidence for implemented workflows — campaign decisions, rationale, audit trails, and selected SOC 2 ITGC mappings with explicit disclaimers. We do not claim certified compliance outcomes.

Do AI agents change access?

No autonomous destructive actions. Agent and MCP support starts with governed questions and bounded requests through Sunder’s API, policy, approval, and audit surfaces.

What does success look like?

A scoped identity/access graph, actionable findings, a completed review campaign, review and approval decision evidence, and an evidence export accepted by your security/GRC owner.
